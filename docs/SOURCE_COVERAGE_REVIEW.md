# SOURCE COVERAGE REVIEW — HK City Monitor

**What this is.** A measurement, not an opinion piece. Every number below came from a script or an
HTTP request run against this working tree on **2026-09-25**; every claim about a source being
usable or unusable either cites a probe result or says `NOT PROBED` in as many words.

**Scope of the question.** `sources.json` holds **176** entries. Cyrus's read was "I think now not
much, it should be 100+". The measured answer is that **49** are referenced by something this
product ships, and **126 are referenced by nothing at all** — but "referenced by nothing" is a fact
about the *configuration*, not about the *source*. Sections 2 onwards separate the two.

**The one thing this report does not do.** It does not say a source is dead. Of the 126
unreferenced entries, **53 were actually requested** and **73 were not**. Section 5 lists what was
not tested, and why.

## 1. The measured numbers

### 1.1 The command

A throwaway Node script (not added to the repo) reads the shipped registries plus the source tree and
classifies every registry id:

```js
// %TEMP%\hkcm-refs2.mjs   —   run as:   cd C:\hk-city-monitor; node %TEMP%\hkcm-refs2.mjs
// (1) shipped config registries:  panels.json (.source and the params keys list_source |
//     expand | fallback_source),  layers.json (.source),  verticals.json (trigger.source,
//     walked recursively)
// (2) every id, matched as a whole word, against web/src + worker/src + scripts + web/scripts
//     (backup files (*.bak-*) and the generated Worker whitelist are excluded)
// (3) the ADAPTERS map extracted from web/src/lib/adapters.ts — the runtime registry that
//     decides whether a panel can actually render
// A. SHIPPED  = a config-registry hit, or an adapter, or a web|worker src hit
// B. TOOLING  = named only by scripts/ or web/scripts/probe-* (never by shipped config)
// C. ORPHAN   = no config, no adapter, no code, no probe
```

Registry-wide facts that matter for the next two sections:

* **9 unreferenced entries carry no `license` field at all** — `td_speedmap`, `td_journeytime`,
  `urbtix_event_batch`, `adsbdb`, `airplanes_live`, `centaline_ccl`, `sunferry_eta`, `hkkf_eta`,
  `ck_wkcda_wkcarpark_wkcarpark`. The registry's own schema comment says a missing licence means
  "deliberately left blank rather than guessed, because a wrong licence is worse than an absent one",
  so these cannot be cleared for use as they stand.
* **46 of the 126 are `auto: true`** — bulk-imported from a CKAN catalogue scan whose only note is
  "Auto-imported from the CKAN full scan (catalogue tier, unreviewed)". They are a catalogue, not a
  curated shortlist.
* **19 of the 126 are `todo: true`.**
* **0 entries are `auth: "paid"`.** 4 are `free-key` (the three Open3Dhk 3D tilesets + AISStream),
  2 are `register`. The metered-key prohibition has held.
* **174 distinct URLs across 176 entries.** The two collisions are `yahoo_hsi` / `yahoo_hk_quotes`
  (identical URL — `yahoo_hsi` is a dead alias) and `td_speedmap` / `td_journeytime` (both URLs are
  the **empty string** with `fetch: "n/a"`).
* The Worker whitelist is in sync with the registry: **67 registry hosts, 67 whitelisted hosts, 0
  missing, 0 extra**, measured against `worker/src/whitelist.generated.js` (generated by
  `scripts/build_worker_whitelist.py`). Nothing in the registry needs a whitelist regeneration
  before it can be wired through the proxy.

### 1.6 What the probes observed about CORS

Every probe was a **server-side** request (Node `fetch`), so this report never treats a missing
`Access-Control-Allow-Origin` as a defect: the registry's `cors_note` field already records the
browser-side answer, and the Worker proxies any registry host. The probe recorded the `ACAO` header
anyway, and it corroborates the registry's `fetch` field in every case:

| observed | count | meaning |
|---|---|---|
| `ACAO: *` (or an echo of the caller's Origin) | 22 | `fetch: "browser"` is correct — the page may call it directly |
| no `ACAO` header | 18 | `fetch: "proxy"` is correct — the Worker must serve it, exactly as the registry says |

**0 probe results contradicted the registry's `fetch` field.** That is a bounded claim: it covers the
40 ids probed by this review's own scripts, not the 136 it did not probe. (The ACAO column was not
recorded for the probes that came back from reviewer subagents, so those are outside even this
bounded claim.)

### Registry hygiene worth doing alongside any of the above

1. **`url: ""` on two entries** (`td_speedmap`, `td_journeytime`) makes them unprobeable and leaves a
   permanent false "unresolved" in `SOURCES.md`. Mark them `todo: false` with the reason, or give
   them the successor URL.
2. **Nine unreferenced ids have no `license` field.** Two of them (`urbtix_event_batch`,
   `ck_wkcda_wkcarpark_wkcarpark`) return perfectly good live data — exactly the situation the blank
   field exists to prevent: a usable payload with no permission recorded.
3. **R1 — the basemap is not in the registry by reference.** `web/public/basemap/style.json` is
   generated by `web/scripts/sync-data.mjs` and hardcodes the LandsD and Esri tile URLs, so
   `landsd_basemap_tiles`, `landsd_label_tiles`, `landsd_imagery_tiles`, `esri_world_imagery` and
   `carto_dark_style` all read as "unreferenced" while the map depends on them. If LandsD moves a
   path, no registry entry needs editing and `validate_config.py` — which walks `sources.json`, not
   the generated style — stays green. That is the same class of defect as Pitfall 27's dead CSS
   selector: a reference that looks live and matches nothing.
4. **R2 — 46 of the 126 unreferenced entries are uncurated CKAN imports** whose only note is
   "Auto-imported … unreviewed". They dilute every count in this report and will keep doing so. A
   `catalogue: true` flag, or moving them to a second file, would make "who is using this registry"
   answerable at a glance.
5. **A `200` is not evidence of data — the registry needs a shape verdict, not a status.** The
   `ck_hk_td_sm_*` "請下載第二代數據" stubs are 200s, and the 1999–2013 API archive is a 200. Both
   would pass any check that watches HTTP status.
